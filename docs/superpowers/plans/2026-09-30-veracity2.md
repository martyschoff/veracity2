# Veracity2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A web app that tracks predictions from named individuals across categories (finance, energy, ukraine, china, ai, geopolitics), compares them against reality via an expert panel, and displays them in a grid where individuals are columns and their predictions (with source URLs) are rows.

**Architecture:** A Python Flask/FastAPI app serving a single-page HTML frontend. Data is stored as JSON files (MVP — no database needed yet). A cron job runs twice daily (8am/8pm) to fetch new YouTube transcripts and other sources for tracked individuals, extract predictions using the LLM, and append them to the data store. The web UI renders the grid from the JSON data.

**Tech Stack:** Python 3.14, FastAPI, Jinja2 templates, yt-dlp for YouTube metadata, youtube-transcript-api for transcripts, JSON file storage, vanilla HTML/CSS/JS frontend.

**Spec:** veracity2 — predictions vs reality tracker

## Global Constraints

- Python 3.14 available on the machine
- No external database — JSON files in `data/` for MVP
- Cron jobs run at 8am and 8pm Eastern via Hermes cron
- YouTube is the primary source; other sources (Substack, podcasts) added later
- Date range starts from 2024-01-01
- Two individuals initially: Peter Zeihan, Doomberg
- Categories: finance, energy, ukraine, china, ai, geopolitics
- Expert panel determination is a future feature — initial version collects and displays predictions only

## Review Focus

1. **Empty transcript** — a YouTube video with transcripts disabled should be skipped gracefully, not crash the fetcher
2. **Duplicate predictions** — re-running the cron job should not create duplicate entries for the same video
3. **Missing category** — a prediction that doesn't fit any predefined category should be labeled "other"
4. **Date parsing** — YouTube upload dates should be parsed correctly across timezones
5. **Large data sets** — the grid should handle 100+ predictions without becoming unresponsive
